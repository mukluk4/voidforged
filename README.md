# Voidforged

A multiclass EverQuest emulator server, built on the
[NMS community release](https://github.com/tunaria/NMS-Release) (itself derived from
[EQEmu](https://github.com/EQEmu/Server)). Every character plays three classes, the level cap is 65,
and the endgame is an endless ladder of Greater Rifts with gear that rolls its own stats.

The player-facing introduction is the **Player's Guide**:
[`Release-NMS-Server/docs/players/Voidforged_Players_Guide.pdf`](Release-NMS-Server/docs/players/Voidforged_Players_Guide.pdf)
(generated by `make_players_guide.py` in the same folder).

---

## What Voidforged adds

| System | What it is | Where |
| --- | --- | --- |
| Greater Rifts | Timed, randomized instances in 26 classic dungeons, tiers 1 to 500, opened by Zebuxoruk in The Void | `utils/scripts/rift/` |
| Dynamic items | Gear that rolls class-weighted stats once, on purchase, stored as a seed | `zone/dynamic_items.*`, `docs/dynamic_items/` |
| Tiered rift gear | Five tiers of class armor, jewelry and augments, unlocked by deepest rift clear | `utils/scripts/dynamic_items/`, `docs/dynamic_items/TIERED_GEAR.md` |
| Set bonuses | Armor sets at 2/4/8 pieces, jewelry sets at 3/6/9 (worn effects, procs, pet focus) | `zone/client.cpp` (`CheckArmorSetBonuses`), `armor_set_bonuses` table |
| Glamours | 18 outfitters selling armor and weapon looks | `utils/scripts/glamour/` |
| Chronal Tributes | Rift-only tributes, paid per rift by tier | `zone/nms_chronal_tribute.*` |
| Paragon AAs | Twelve deep AA lines for HP, mana, AC and heroic stats | `zone/nms_paragon.*` |
| Reforging | Reroll one random line on a rolled item (`#reforge`) | `zone/gm_commands/reforge.cpp` |
| Gear sets | Bandolier sets that swap every worn slot (`#gear`) | `zone/gear_sets.*`, `zone/gm_commands/gear.cpp` |
| Nautilus Vault, `/nmsloot` | Extra storage and personal loot offers per group member | `zone/` |
| Patcher | Self-updating client patcher with a content-addressed file host | `utils/patcher/` |

Paths in the table are under `Release-NMS-Server/`. On top of all this is the NMS base:
multiclassing (three classes per character), multiple pets, item upgrade tiers and the client-side
`dinput8.dll` add-on.

## Layout

| Folder | What it is |
| --- | --- |
| [`Release-NMS-Server/`](Release-NMS-Server/) | The server source (EQEmu-based), generators, SQL and docs |
| [`Release-NMS-Client/`](Release-NMS-Client/) | The `dinput8.dll` client add-on and modified UI files |
| [`Release-NMS-Quests/`](Release-NMS-Quests/) | Base quest scripts (Perl / Lua) from the NMS release |
| [`Release-NMS-Plugins/`](Release-NMS-Plugins/) | Perl plugins the quests depend on |

Voidforged's own quest scripts and Lua modules live with their generators under
`Release-NMS-Server/utils/scripts/rift/`, and are copied into the server's `quests/` and
`lua_modules/` folders when deployed. The content tables (items, spells, vendors, set bonuses, rift
zones) are generated SQL; see the README in each `utils/scripts/` folder.

## Building

Windows (Visual Studio 2022 or later):

```
cmake -S Release-NMS-Server -B Release-NMS-Server/Build
cmake --build Release-NMS-Server/Build --config RelWithDebInfo --target world zone
```

On low-memory machines, build one target at a time with limited parallelism
(`-- -m:1 -p:CL_MPCount=2`). A change to `common/ruletypes.h` needs both `world` and `zone` rebuilt.
The server reads its settings from `eqemu_config.json` next to the binaries; that file holds the
database password and is never committed.

## Database

`Release-NMS-Server/database/voidforged-content.zip` is a snapshot of the live world content: items,
spells, NPCs, spawns, merchants, zones, rules, the rift and dynamic item tables and the set bonuses.
It has no accounts, characters or other player data. To build a fresh server, import the NMS
`release-peq.zip` first (it creates every table, player tables included), then import this snapshot
over it. Refresh the snapshot with `python Release-NMS-Server/utils/scripts/dump_content.py` (MariaDB's
`bin` folder on PATH) and commit the new zip.

The base setup (quests, client data files, client add-on) is the same as the NMS release; see [`Release-NMS-Server/README.md`](Release-NMS-Server/README.md) and
[`Release-NMS-Client/README.md`](Release-NMS-Client/README.md).
